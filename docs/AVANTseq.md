
## 2. AVANTseq Variant Calling Pipeline

### Purpose

Performs somatic variant calling on tumor samples in tumor-only mode using Mutect2 after FASTQ raw data pre-processing. The merged Panel of Normals generated by the [PoN pipeline](PoN.md) (`merged_pon` in `config/config.yaml`) is used to remove recurrent technical artifacts, so run `CreatePoN.smk` first. The following rule graph visualizes the AVANTseq Snakemake workflow structure, highlighting rule dependencies and execution order:

![AVANTseq Snakemake rule graph: trimming, BWA alignment, duplicate marking, QC, Mutect2 calling, contamination estimation, filtering, normalization and Funcotator annotation](dag_avantseq.png "Rule graph for AVANTseq.smk")

### Configuration

Please refer to the sections below for detailed descriptions of:

- The main configuration file `config/config.yaml`, including reference files, target regions and the merged panel of normals.
- The sample list `config/samples_tumor.yaml`, which should contain the list of tumor samples.

### Run the AVANTseq Pipeline

```bash
# run from the repository root
snakemake -s AVANTseq.smk --cores 8
```

### Outputs

The AVANTseq pipeline generates the following output files for each sample, grouped by analysis step. 

---

#### Quality Control and Alignment

- `alignment/bams/{sample}.bam`  
  Analysis-ready reads in **BAM** format: trimmed with **fastp**, aligned with **BWA-MEM**, sorted, duplicate-marked and base-quality recalibrated (**GATK BQSR**).

- `alignment/bams/{sample}.bam.bai`  
  Index file for the BAM, created with **samtools index** for rapid access.

- `alignment/qc/fastqc/{sample}_R1_fastqc.html`, `alignment/qc/fastqc/{sample}_R2_fastqc.html`  
  Quality control reports from **FastQC** on the raw reads (R1 and R2), assessing read quality, GC content, adapter content, etc.  
  [FastQC documentation](https://www.bioinformatics.babraham.ac.uk/projects/fastqc/)

- `alignment/qc/fastp/{sample}_fastp.html`, `alignment/qc/fastp/{sample}_fastp.json`  
  Read trimming reports from **fastp** (adapter content, quality and length filtering, insert size).  
  [fastp documentation](https://github.com/OpenGene/fastp)

- `alignment/qc/markdup/{sample}_dedup_metrics.txt`  
  Duplication metrics from **GATK MarkDuplicates**.

- `alignment/qc/bqsr/{sample}_recal.table`  
  Base quality recalibration model from **GATK BaseRecalibrator**, applied with **ApplyBQSR**.  
  [GATK BQSR](https://gatk.broadinstitute.org/hc/en-us/articles/360035890531-Base-Quality-Score-Recalibration-BQSR)

- `alignment/qc/multiqc_report.html`  
  Aggregated report from **MultiQC**, summarizing FastQC, fastp, samtools, MarkDuplicates and BQSR metrics across all samples.  
  [MultiQC documentation](https://multiqc.info/)

---

#### Coverage and Hybrid Capture QC

- `variants/qc/CoverageSummary.txt`  
  Read counts over the covered regions for all samples, calculated with **deepTools multiBamSummary** (a compressed matrix, `CoverageSummary.npz`, is also produced).

- `variants/qc/HsMetrics/{sample}_metrics.txt`  
  Hybrid selection metrics generated with **GATK (Picard) CollectHsMetrics**, including on/off-target efficiency, mean target coverage, and bait performance.  
  [Picard CollectHsMetrics](https://broadinstitute.github.io/picard/command-line-overview.html#CollectHsMetrics)

---

#### Variant Calling (Mutect2)

- `variants/mutect2/{sample}.vcf.gz`  
  Raw somatic variant calls generated by **GATK Mutect2**, identifying SNVs and indels.  
  [GATK Mutect2](https://gatk.broadinstitute.org/hc/en-us/articles/360037593851-Mutect2)

- `variants/mutect2/{sample}.f1r2.tar.gz`, `variants/mutect2/{sample}.read-orientation-model.tar.gz`  
  F1R2 read orientation counts collected by Mutect2 and the orientation bias model learned with **LearnReadOrientationModel**, used by FilterMutectCalls to remove artefacts such as FFPE deamination and oxoG damage.

- `variants/mutect2/{sample}.getpileupsummaries.table`  
  Table summarizing read counts at common germline sites, used for contamination estimation.

- `variants/mutect2/{sample}.calculatecontamination.table`  
  Estimated contamination levels per sample, based on pileup summaries.

- `variants/mutect2/{sample}.segments.table`  
  Tumor segmentation (minor allele fraction segments) produced by **GATK CalculateContamination**, used by FilterMutectCalls.

---

#### Filtering and Annotation

- `variants/filtered/{sample}_filtered.vcf.gz`  
  Variant calls annotated by **FilterMutectCalls** using the contamination estimate, tumor segmentation and orientation bias priors. Variants that fail a filter are kept but flagged in the `FILTER` column.

- `variants/filtered/{sample}_filtered_norm_dec.vcf.gz`  
  Decomposed (`vt decompose -s`, multi-allelic sites split together with their per-allele fields) and then left-normalized (`vt normalize`) VCF, with `.tbi` index, prepared for annotation using **vt**.  
  [Unified representation of genetic variants](https://academic.oup.com/bioinformatics/article/31/13/2202/196142)

- `variants/maf/{sample}.maf`  
  Final annotated variant list in **Mutation Annotation Format (MAF)**, produced with **Funcotator**, suitable for reporting and downstream analysis. Only variants that pass all filters are included.  
  [Funcotator documentation](https://gatk.broadinstitute.org/hc/en-us/articles/360037593891-Funcotator)

---

### Notes and limitations

- **Tumor-only calling.** Without a matched normal, rare germline variants that are absent from gnomAD and from the Panel of Normals can remain in the final output. Interpret variants with a population allele frequency close to 0 and a VAF around 50% or 100% with care.
- **Germline and PoN sites in the raw VCF.** Mutect2 runs with `--genotype-germline-sites` and `--genotype-pon-sites`, so the raw and filtered VCFs also contain these sites (flagged as `germline` or `panel_of_normals`). This keeps them available for downstream analyses such as clonality; they are removed from the final MAF.
- **Contamination on small panels.** The contamination estimate is based on common germline sites inside the target regions. With small panels only a few informative sites are available, so the estimate is less precise.
